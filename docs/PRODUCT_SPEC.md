# CubeCoach 제품 명세

- 상태: Draft
- 기준일: 2026-07-31
- 첫 플랫폼: iOS 17 이상
- 첫 퍼즐: 3×3×3

## 1. 제품 정의

CubeCoach는 실제 큐브를 사용하는 사람의 **공식 회상, 케이스 인식, 실행, 실전 전이**를 훈련하는 iOS 앱이다.

> **학습 경험 재설계:** 기존 평문·자기평가형 트레이너는 일반 회상·분산 연습 근거를 큐브의 시각·운동 과제에 과도하게 확장했다. 새 제품 계약은 [`LEARNING_EXPERIENCE.md`](LEARNING_EXPERIENCE.md)의 `시작 상태 준비 증거 → 큐브 상태 → 방향 → 실제 동작 → 기대 상태 → 지연 회상`이며, 평문·공식 문자열 답안과 기억 난이도 자기평가를 사용하지 않는다.

### 대전제

> 큐브를 대신 해결해 주는 앱이 아니라, 공식을 암기할 수 있게 해 주고 큐브 솔빙 실력을 증대시키는 앱이다.

이 대전제는 기능 우선순위와 화면의 기본 동작을 결정한다.

- 앱은 사용자가 먼저 생각할 시간을 준다.
- 전체 공식과 해결 순서를 기본값으로 노출하지 않는다.
- 카메라 인식은 케이스를 찾고 연습을 준비하는 보조 수단이다.
- 해결 엔진은 커리큘럼 판정, 스크램블 생성, 사후 비교에 쓸 수 있지만 자동 해결 흐름이 제품의 중심이 아니다.
- 사용자의 현재 결과는 “앱을 따라 큐브가 맞춰짐”이 아니라 최고 도움, playback, 인식 결과와 실물-도식 수동 비교로 기록한다. 지연 구간과 유효 상태 스캔 증거는 후속 스키마다.

### 현재 프로토타입과 목표의 경계

- 현재 구현: 서명된 TNoodle-WCA 1.2.3으로 사전 생성하고 checksum을 검증한 **32,768개 개인 연습용** 스크램블
- 후속 목표: 사실상 무제한으로 제공할 수 있는 검증된 random-state 자유 연습 생성
- 공식 대회: 당시 WCA 공식 TNoodle과 별도 운영 절차의 영역이며 CubeCoach 프로토타입이 제공하지 않음
- 현재 스캔: 표준 6색 배치의 큐브를 고정 안내선에 맞춰 `U/F/R → D/L/B`로 촬영하고 기기 안에서 투시 보정·3×3 색 표본·센터 기준 Lab 분류를 수행하는 두 포즈 입력
- 현재 상태 처리: 자동 54칸 후보와 셀별 신뢰도를 만들고, 수동 교정 후 색 수·조각 유일성·코너/엣지 방향 합·cubie permutation parity를 검사하여 다음 학습 단계를 추천. 이는 OLL/PLL의 정확한 개별 케이스 matcher가 아니라 단계 진단임
- 스캔 경계: 임의 사진 속 큐브를 찾는 detector, 비표준 색 배치, 모든 조명·반사·재질에서의 무수정 인식은 지원 범위가 아니며 실기기 정확도 검증이 남음
- 현재 타이머 UI: 추가 탐색 깊이와 세로 스크롤 없이 한 화면에 둔 인라인 내비게이션, 모드 선택, TNoodle 연습 스크램블, 같은 스크램블을 적용한 축약 54칸 검산 전개도와 U/F 기준, 타이머·주요 조작, 방금 기록과 페널티 수정
- 현재 기록 UI: PB, session mean, 완주율, 최근 일관성, current/best ao5·ao12, 최근 10/25/50회의 시간 추세, 최근 기록과 학습·약점 통계
- 후속 통계: ao100, median, 분포, 다중 기록 편집과 내보내기
- 현재 출시 학습 UI: 초급 레이어 해법의 기초 샘플과 2-Look CFOP 입문 샘플만 노출하며, Full CFOP·고급 분석·최단해 비교는 장기 비전으로 남겨 출시 UI에 placeholder를 두지 않음
- 현재 복습: 내부 `TrainerView`가 고정 방향 2D net, move stepper, 단계별 도움, 시각 케이스 판별, 실제 큐브 실행과 기대 상태 수동 비교를 구현. `트레이너`는 독립 탭이나 사용자-facing 명칭이 아님. 이는 시뮬레이터·자동 테스트를 통과한 제품 가설이며 큐브 전용으로 효과가 검증된 학습법이라는 뜻은 아님
- 포함 자산: 기본·다크·틴트용 1024px AppIcon 이미지와 로컬 데이터용 개인정보 매니페스트

## 2. 문제

큐브 학습자는 다음 단절을 겪는다.

1. 영상이나 공식표를 볼 때는 이해한 것 같지만 실제 큐브 앞에서 떠올리지 못한다.
2. 같은 공식도 케이스 방향이 달라지면 인식하지 못한다.
3. 초급 해법에서 F2L·2-Look OLL/PLL·Full CFOP으로 넘어갈 순서를 알기 어렵다.
4. 타이머는 빨라졌는지 보여 주지만 어느 케이스에서 막혔는지는 설명하지 않는다.
5. 기존 자동 해결기는 완성에는 도움을 주지만, 지시를 제거했을 때 독립 솔빙으로 잘 전이되지 않을 수 있다.
6. 큐브 상태를 여섯 면씩 수동 입력하는 과정은 연습 진입 비용이 높다.

## 3. 제품 목표와 비목표

### 목표

- 공식을 보지 않은 지연 물리 시도에서 기대 상태 일치율을 높이는지 검증한다.
- 시작 상태와 방향을 보고 실제 큐브에 동작을 적용한 뒤 기대 상태와 비교하게 한다.
- 케이스를 다양한 방향과 인접 케이스 사이에서 구별하게 한다.
- 도움을 점진적으로 줄여 독립 실행으로 옮긴다.
- 출시 범위에서는 초급 기초 → 2-Look CFOP 입문의 학습 경로를 제공한다.
- Full CFOP과 고급 분석은 콘텐츠 정확성·권리·상태 적용 검증을 마친 후 별도 릴리스로 확장한다.
- 스크램블·검사·타이머·통계로 학습 결과를 실제 솔빙에서 확인한다.
- 두 번의 다면 촬영으로 상태 입력 부담을 낮추되, 불확실한 결과는 사용자가 확인하게 한다.

### 비목표

- 사진을 찍으면 전체 해결 동작을 끝까지 읽어 주는 자동 해결기
- WCA 공인 대회용 타이머 또는 스크램블 시스템
- MVP에서 2×2, 4×4 이상과 모든 트위스티 퍼즐 지원
- 모든 해법을 하나의 “초급/중급/고급” 보편 등급으로 규정
- 모든 상태에 대해 수학적으로 최적인 해를 즉시 보장
- 커뮤니티 자료를 출처·권리 검수 없이 복제한 공식 데이터베이스
- 평문 답안·공식 문자열 입력·기억 난이도 자기평가를 실제 실행의 대리 지표로 사용
- 불완전한 초급/2-Look 샘플을 완결된 커리큘럼 또는 숙달 과정으로 홍보

## 4. 페르소나

### P1. 공식을 자주 잊는 입문자

- 상황: 영상으로 3×3을 한두 번 맞춰 봤지만 며칠 지나면 마지막 층 공식을 잊는다.
- 목표: 공식표 없이 처음부터 끝까지 맞추고 싶다.
- 불편: 표기법과 큐브 방향이 낯설고, 실패하면 어느 동작에서 틀렸는지 모른다.
- 필요한 경험: 작은 동작 묶음, 반복 회상, 친절한 오류 복구, 실제 큐브 중심 연습

### P2. 초급에서 CFOP으로 전환하는 성장형 큐버

- 상황: 초급 해법으로 1–2분대 솔빙이 가능하며 기록을 줄이고 싶다.
- 목표: 직관적 F2L과 2-Look OLL/PLL을 익혀 불필요한 멈춤을 줄이고 싶다.
- 불편: 무엇부터 배울지, 기존 습관을 언제 바꿀지, 새 공식이 실전에서 왜 나오지 않는지 모른다.
- 필요한 경험: 선행 조건이 있는 로드맵, 케이스별 드릴, 혼합 연습, 타이머 전이 확인

### P3. OLL·PLL을 확장하는 중급 큐버

- 상황: 2-Look을 쓰며 Full OLL/PLL 또는 대체 공식을 선택적으로 익힌다.
- 목표: 비슷한 패턴을 빠르게 구분하고 자신의 손에 맞는 공식을 안정적으로 실행하고 싶다.
- 불편: 외운 개수가 많아질수록 오래된 케이스를 잊고, 공식은 기억해도 AUF·방향 인식이 느리다.
- 필요한 경험: 간격 복습, 유사 케이스 인터리빙, 여러 각도의 인식, 최고 도움 단계와 실행 시간 분리

### 보조 페르소나

- 대회를 준비하며 15초 검사와 +2/DNF 규칙을 연습하려는 큐버
- 자녀의 학습 진도를 보되 자동 해결에 의존시키고 싶지 않은 보호자
- 색각 차이, 큰 글자, 음성 표기 등 접근성 지원이 필요한 사용자

## 5. Jobs To Be Done

| 상황 | 하고 싶은 일 | 기대 결과 |
| --- | --- | --- |
| 짧은 시간이 생겼을 때 | 오늘 잊기 쉬운 케이스만 복습한다 | 5–10분 안에 의미 있는 학습을 끝낸다 |
| 실제 큐브에서 낯선 패턴을 만났을 때 | 이 상태가 어떤 케이스인지 확인한다 | 전체 답을 보기 전에 스스로 공식을 떠올린다 |
| 공식이 생각나지 않을 때 | 필요한 만큼만 힌트를 연다 | 막힘은 해소하되 회상 시도는 보존한다 |
| 새 해법으로 넘어갈 때 | 현재 실력에 맞는 다음 단계를 찾는다 | 너무 많은 공식을 한꺼번에 배우지 않는다 |
| 연습 결과를 확인할 때 | 스크램블과 타이머로 자유 솔빙한다 | 배운 케이스가 실전에 전이됐는지 안다 |
| 기록이 정체됐을 때 | 시간 손실과 약한 케이스를 본다 | 다음 연습 과제가 구체적으로 정해진다 |
| 촬영 인식이 틀렸을 때 | 불확실한 칸만 수정한다 | 여섯 면 전체를 다시 입력하지 않는다 |

## 6. 학습 모델

### 6.1 학습 단위

각 학습 항목은 다음을 가진다.

- 안정적인 `caseID`
- 해법/단계/패밀리
- 선수 학습
- 여러 방향의 인식 예시
- 핵심 구별 특징
- 기본 공식과 허가된 대체 공식
- 손동작을 위한 의미 있는 청크
- 흔한 오류와 복구
- 출처, 버전, 라이선스/사용 허가 상태
- 시작 상태 ID, 방향 ID, move별 기대 상태
- 현재 복습 상태: 시작·완료 시각, 준비 방식, 최고 도움 H0–H5, playback, 인식 결과, 실행 비교, 수동 증거, 모드, 결정적 콘텐츠 버전. 지연 구간과 스캔 증거는 후속

이론 전용 항목은 구조·표기·단계 개요를 설명할 수 있지만 시작 상태·move sequence·기대 상태가 없으므로 복습 큐에 들어가지 않는다.

### 6.2 한 번의 물리 회상 사이클

1. **시작 상태 준비 증거:** 앱 밖에서 이미 정확히 준비했는지, 정답 역순의 설정 도움을 사용했는지 기록한다.
2. **큐브 상태:** 검증된 시작 상태를 고정 방향 2D net으로 제시한다.
3. **방향:** 사용자가 실제 큐브의 기준 면을 맞춘다.
4. **실제 동작:** 공식 문자열을 입력하지 않고 실제 큐브를 돌린다.
5. **도움 선택:** 막힐 때만 H0–H5의 다음 단계를 연다.
6. **기대 상태:** 단계별 또는 최종 2D net과 실물을 비교한다.
7. **결과:** 현재는 `같음/다름/모름` 수동 비교를 기록한다. 유효 상태 스캔을 이용한 사후 정확 비교는 후속이다.
8. **지연 회상:** 같은 항목을 후속 시점에 동작열을 가린 상태로 다시 수행한다.

### 6.3 학습과학의 적용 범위

- 회상 연습과 분산 연습은 장기 기억을 위한 강한 일반 근거가 있다.
- 인터리빙은 비슷한 케이스의 구별에 유용할 수 있으나 과제 특성에 따라 효과가 달라질 수 있다.
- 초보자에게는 완성 예시가 필요하고, 숙련이 늘면 도움을 줄이는 방식이 적합하다는 근거가 있다.
- 이 근거가 곧바로 “큐브 기록을 몇 초 단축한다”는 임상적·인과적 보장은 아니다. 제품 내 효과는 별도 실험으로 검증한다.
- 기존 평문·자기평가형 트레이너는 이 일반 근거의 직접적 결론이 아니며 폐기할 제품 추론이다.
- 애니메이션·관찰 학습·운동 청킹 연구는 2D stepper와 물리 수행을 시도할 근거를 보완하지만 3D 우월성이나 CubeCoach의 효과를 보장하지 않는다.

## 7. 도움 사다리

도움 사다리는 실행 가능한 복습 항목의 내부 계약이다. UI에는 H 번호나 `guidedAcquisition` 같은 값을 노출하지 않고 구체적인 도움 행동을 표시한다. 현재 설정은 정답 동작열의 역순을 보여 주는 습득 지원이며 복습 안에서 사용하면 `preparation=guidedAcquisition`으로 같은 시도에 기록한다. 사용자가 앱 밖에서 정확한 시작 상태를 이미 만들었다고 명시한 경우에는 `preparation=externallyPrepared`를 기록한다.

| 단계 | 표시 내용 | 기록 |
| --- | --- | --- |
| H0 시작 상태 | 준비 방식을 기록한 뒤 케이스 이름과 공식을 숨긴 시작 2D 상태를 사용한다. 시각 후보 선택은 인식 증거만 생성 | `maxHint=H0` |
| H1 시각 인식 단서 | 케이스를 구별하는 스티커·조각 판별 단서 | `maxHint=H1` |
| H2 방향·표기 | 잡는 방향, `U/F` 기준 면, 시계 방향 판정과 표기 프라이머 | `maxHint=H2` |
| H3 첫 move | 첫 move와 적용 전·후 상태 | `maxHint=H3` |
| H4 첫 의미 청크 | 첫 검수 청크의 move와 단계 이동 가능한 상태 | `maxHint=H4` |
| H5 전체 stepper | 전체 move sequence와 모든 단계의 기대 상태 | `maxHint=H5` |

규칙:

- 다음 단계는 사용자가 명시적으로 연다.
- 한 번 연 힌트는 해당 시도 기록에 남긴다.
- 현재 복습 스케줄은 실행 비교, 최고 도움, playback과 인식 교정 여부를 사용한다. 지연 구간과 스캔 증거를 직접 저장·활용하는 것은 후속이다.
- `guidedAcquisition`, 준비 증거 누락, H1–H5, playback 또는 인식 교정을 사용한 일치는 지원된 수행이며 독립 회상이나 숙달로 세지 않는다.
- 독립 H0 후보는 `externallyPrepared`를 명시하고 H1–H5·playback·인식 교정을 사용하지 않은 시도뿐이다.
- 오류 복구는 학습 화면의 습득 지원으로 제공하고 별도 H6 숙련 단계로 만들지 않는다.
- 수동 비교에는 `검증됨`을 표시하지 않는다. 후속 `validatedScan`을 통합하더라도 유효 상태 검사와 기대 상태 비교를 통과한 결과에만 이 라벨을 사용한다.

### 7.1 시도 결과 계약

현재 `ReviewAttempt`는 다음 필드를 저장한다.

- `caseID`, `startedAt`, 완료 시각인 `timestamp`
- `preparation` (`externallyPrepared/guidedAcquisition`; 레거시 기록은 `nil` 가능)
- `maxHint` (`H0`–`H5`), `playbackUsed`
- `recognition` (`correct/corrected/notAssessed`)
- `execution` (`matched/didNotMatch/unsure`)
- `evidence` (현재 `manualComparison`)
- `mode` (`learning/review/practice/scanRecommendation`), `contentVersion`

시각 후보 선택은 `recognition` 증거일 뿐 실행 답안이 아니다. 실제 큐브 실행 뒤 사용자가 기대 2D 상태와 비교한 결과만 `execution`에 저장한다. `preparation != externallyPrepared`, `maxHint > H0`, playback 사용 또는 인식 교정이 있으면 지원된 시도로 분류한다. 기억 난이도는 묻지 않으며 스케줄러 등급은 이 시도 증거에서 내부 파생한다.

`contentVersion`은 케이스 ID, 인식 설명, 공식, 설정과 청크에서 FNV-1a 64비트로 계산한 결정적 값이다. 콘텐츠가 달라지면 해당 케이스의 스케줄 기준을 새로 시작한다. 이 값은 변경 감지용이며 보안 해시가 아니다.

`startStateID`, `orientationID`, `algorithmID`, `delayBucket`, `elapsed`는 후속 분석 스키마다. 현재 저장된다고 간주하지 않는다.

- `manualComparison`: 사용자가 실물과 기대 2D 상태를 비교한 보고. 자동 정확 검증이 아니다.
- `validatedScan`: 향후 실제 iPhone 데이터셋과 사후 기대 상태 비교를 검증한 뒤 생성할 증거. 현재 카메라는 복원한 상태의 유효성을 검사하고 학습 단계를 진단한 뒤 `scanRecommendation` 대표 연습을 추천하지만, 촬영한 54칸을 트레이너 시작 상태로 전달하거나 실행 결과와 정확 비교하지 않는다.

`검증됨`은 후속 `validatedScan` 통합이 완료된 결과에만 사용할 수 있다. 현재 수동 결과에는 표시하지 않는다.

## 8. 커리큘럼

`초급`, `중급`, `고급`은 WCA가 정한 공식 등급이 아니다. CubeCoach의 제품 라벨이며, 화면에서는 실제 내용명과 함께 표시한다.

2026-07-31 출시 UI는 **초급 레이어 해법의 기초 샘플**과 **2-Look CFOP 입문 샘플**만 노출한다. 아래 트랙 A·B의 전체 목록과 완료 기준은 커리큘럼을 닫기 위한 목표이며, 현재 카탈로그가 완전한 독립 솔빙 또는 완결된 2-Look 공식을 제공한다는 뜻이 아니다. 트랙 C·D는 출시하지 않은 장기 비전으로만 관리하고 앱에 `준비 중` 행을 두지 않는다.

### 트랙 A — 첫 독립 솔빙 목표

- 큐브 구조와 센터/엣지/코너
- Singmaster 기본 표기
- 1층 크로스
- 1층 코너
- 2층 엣지
- 마지막 층 방향 맞추기
- 마지막 층 위치 맞추기
- 전체 예제 솔브와 실수 복구

완결 커리큘럼이 확보된 뒤 검증할 목표 기준 예:

- 서로 다른 유효 시작 상태에서 전체 단계를 실제 큐브로 수행한다.
- 서로 다른 연습용 스크램블 3회 이상을 독립 완성한다.
- 공식 공개 없이 마지막 층 케이스를 재현한다.

### 트랙 B — 중급 전환 목표

- 크로스를 아래에서 계획하기
- 직관적 F2L 기본 원리와 대표 케이스
- 2-Look OLL
- 2-Look PLL
- 기본 핑거트릭과 불필요한 큐브 회전 줄이기

완결 커리큘럼이 확보된 뒤 검증할 목표 기준 예:

- 블록 연습뿐 아니라 혼합 솔빙에서 케이스를 인식한다.
- 15초 검사에서 크로스 일부 또는 전체를 안정적으로 계획한다.
- 2-Look 마지막 층을 전체 공식 공개 없이 수행한다.

### 트랙 C — Full CFOP 장기 비전(미출시)

- F2L 확장과 lookahead
- 57 OLL
- 21 PLL
- AUF와 다각도 인식
- 사용자의 손에 맞는 대체 공식

완결 커리큘럼이 확보된 뒤 검증할 목표 기준 예:

- 지연 복습에서 목표 무힌트 성공률을 유지한다.
- 유사 케이스 혼합 세트에서 정해진 정확도에 도달한다.
- 자유 솔빙에서 해당 케이스가 나왔을 때 멈춤 없이 적용한다.

### 트랙 D — 고급 분석 장기 비전(미출시)

- 고급 F2L, COLL 등 선택 모듈
- 솔브 재구성, 회전·regrip·move count 분석
- 짧은 해/준최단 해와 사용자의 해법 비교
- Fewest Moves는 별도 종목·학습 체계로 분리

고급 분석은 “더 많은 공식 = 무조건 더 빠름”으로 제시하지 않는다.

### 9.6 타이머·통계 벤치마크

[CubeTime 한국 App Store](https://apps.apple.com/kr/app/cubetime/id1600392245)을 사용자 지정 1순위 타이머·통계 벤치마크로 삼는다. CubeTime의 미니멀한 타이머, session/multiphase/comp sim, current/best ao5·ao12·ao100, mean·median·best single, 추세·분포 그래프, 일괄 기록 편집·내보내기, 설정 범위를 참고한다.

CubeCoach는 다음처럼 구분한다.

- 외형과 화면 구성을 복제하지 않고, 작은 화면에서의 저마찰 측정과 점진적 통계 탐색 원칙을 참고한다.
- 탭과 화면 제목은 `연습` 하나로 통일한다. `스크램블-타이머`를 누른 뒤 `스피드 타이머`로 바뀌던 이름 혼용은 목적을 설명하지 못하는 이전 구조였으며 유지할 근거가 없다.
- 연습 탭을 열거나 오늘 CTA를 누르면 같은 직접 루트에 도착한다. 중간 허브나 타이머 상세 push는 두지 않는다.
- 타이머 기본 화면은 스크롤 없이 한 viewport에 맞추고, WCA 방식 인스펙션도 같은 주요 조작 영역에서 시작한다.
- 정지 상태는 최신 시간과 페널티만 남기고 다음 스크램블을 정확히 한 번 게시한다. 상세 통계는 기록 화면으로 분리하며 타이머 하단의 평균·최근 12개 목록은 두지 않는다.
- 일반 기록에는 PB, current/best 평균, 추세, 완주율, 일관성을 제공한다.
- 같은 화면 흐름에서 힌트 없이 회상한 비율, 힌트 의존도, 약한 케이스를 연결한다.
- 현재 번들 출력을 `WCA 공식 스크램블`, `공인 대회용`, `WCA 승인 앱`으로 오표기하지 않는다.

현재 프로토타입은 기록 탭에서 PB, session mean, 완주율, 최근 일관성, current/best ao5·ao12, 최근 10/25/50회의 시간 추세와 기본 학습·약점 통계를 노출한다. 연습 탭은 이 값을 중복하지 않는다. ao100, median, 분포, 다중 기록 편집과 내보내기는 후속 범위다.

## 10. 주요 사용자 흐름

### 10.1 오늘의 복습

`오늘 → 복습 시작 → 시작 상태 준비 → 단서를 가리고 실제 실행 → 필요 시 단계별 도움 → 기대 상태 비교 → 증거와 결과 저장 → 다음 케이스`

완료 조건:

- 현재 세션은 최고 도움과 수동 비교 결과를 저장하고 다음 복습일을 계산한다. 지연 구간과 스캔 증거 표시는 후속이다.
- 평문 답안과 기억 난이도는 요구하지 않는다.

### 10.2 스크램블·타이머

`연습 → 스크램블 표기와 54칸 전개도 원자적 준비 → 실제 큐브에 적용·검산 → 검사 옵션 → 타이머 → 화면 어디든 touch-down으로 정지 → 방금 기록 → +2/DNF 수정`

완료 조건:

- 스크램블 문자열, 생성 방식, 시드/식별자, 시간, 페널티가 한 기록으로 보존된다.
- 스크램블 표기와 전개도는 같은 상태를 나타내며 한쪽만 준비된 상태를 사용자에게 제시하지 않는다.
- 통계 탐색은 기록 탭으로 이동하며 연습 화면에 평균이나 최근 기록 목록을 중복하지 않는다.
- 오늘의 `연습 시작`은 내비게이션 stack을 늘리지 않고 연습 탭을 선택한다.
- 연습 화면은 세로 스크롤 없이 인라인 내비게이션·모드·스크램블·축약 검산·타이머·주요 조작을 한 화면에 유지한다.

### 10.3 2포즈 스캔

`연습 → 내 큐브 스캔 → 개인정보 설명/권한 → 포즈 A 정렬 → 촬영 → 반대 꼭짓점으로 전환 → 포즈 B 촬영 → 낮은 신뢰도 수정 → 상태 유효성 검사 → 단계 진단 → 대표 연습 추천`

완료 조건:

- 54개 스티커와 큐비 상태가 유효하거나, 수정 가능한 구체적 오류가 표시된다.
- 스캔 후 기본 행동은 진단 단계에 대응하는 대표 연습으로 이동하는 것이다. 추천 전개도는 촬영한 54칸 상태 자체가 아니다.
- “전체 해결 보기”를 제공하더라도 학습 흐름 밖의 명시적 고급 분석으로 둔다.

## 11. 타이머 요구사항

### 기본

- 단조 시계를 사용한 시간 측정
- 실행 중 내비게이션·탭·상태 chrome을 숨기고 화면 어디든 첫 touch-down으로 정지하는 큰 타이머
- WCA 방식 인스펙션과 일반 측정이 공유하는 하나의 주요 조작 위치
- 실행 중 전체 화면의 첫 touch-down에서 정지. 버튼이나 특정 카드에 정확히 맞출 필요가 없어야 함
- 동일 실행에 연속 touch-down 또는 접근성 액션이 들어와도 기록과 새 스크램블을 한 번만 생성하는 멱등 정지
- VoiceOver 사용자가 같은 정지 동작을 수행할 수 있는 전체 정지 표면의 접근성 액션
- 솔브 중 집중을 방해하지 않는 최소 정보와 빠른 다음 시도
- 스크램블과 기록 연결
- 방금 기록 표시와 +2/DNF 수정
- 백그라운드 전환·중단 상태를 명확히 처리

### 통계

- 기본 요약: PB, best single, current/best ao5·ao12, session mean
- 충분한 기록 이후: current/best ao100, median
- 변화 확인: 세션·기간별 추세
- 신뢰도 확인: 완주율과 최근 유효 기록의 일관성
- 학습 연결: 무힌트 회상률, 힌트 의존도, 약한 케이스
- 기록 관리: 다중 선택 후 페널티 수정·세션 이동·삭제, 원시 데이터 내보내기
- 그래프와 색만으로 정보를 전달하지 않고 같은 값을 텍스트·표로도 제공

현재 프로토타입은 PB, session mean, 완주율, 최근 일관성, current/best ao5·ao12와 최근 10/25/50회의 시간 추세를 기록 화면에 표시한다. ao100, median, 분포, 다중 기록 편집과 내보내기는 구현하지 않았다.

통계의 사용자-facing 단일 소스는 기록 탭이다. 연습 탭은 평균·최근 12개 목록·PB 요약을 중복하지 않고, 솔브 직후 최신 시간·페널티 확인과 정지당 한 번 게시되는 다음 스크램블만 담당한다.

### WCA 규정 연습 모드

2026-07-30에 확인한 WCA 규정의 연습 가능한 핵심:

- 검사 시작 후 8초·12초 안내
- 15.00초부터 +2
- 17.00초부터 DNF

이 기능은 `WCA 규정 연습`으로 표시한다. 휴대폰 터치 타이머는 Stackmat과 심판 절차를 대체하지 않으며 공식 기록을 생성하지 않는다.

## 12. 스크램블 요구사항

현재 프로토타입은 TNoodle-WCA 1.2.3 공식 서명 JAR로 오프라인 생성한 32,768개 고유 3×3 출력과 provenance manifest를 번들한다. 런타임에는 유한 카탈로그에서 재현 가능한 index를 선택하며, 앱 자체가 TNoodle을 실행하거나 새 random-state를 생성하지 않는다.

### 자유 솔빙

- 3×3 자유 솔빙은 TNoodle 1.2.3 사전 생성 번들을 기본으로 한다.
- 같은 seed와 카탈로그 checksum으로 선택 결과를 재현할 수 있어야 한다.
- 전체 카탈로그의 checksum, 중복, 표기 파싱을 검증한다.
- 선택한 스크램블 표기와 이를 `CubeState.solved`에 적용한 54-facelet 상태를 하나의 성공 결과로 갱신한다.
- 표기 파싱, 상태 적용, 전개도 생성 중 하나라도 실패하면 기존 표기나 전개도를 새 값과 섞지 않고 스크램블 상태를 실패로 전환해 타이머를 잠근다.
- 검산 전개도는 표준 배색의 흰색 윗면(U)을 위, 초록 앞면(F)을 앞에 둔다.
- “대략 20개의 무작위 회전”을 공정한 상태 분포와 같은 것으로 취급하지 않는다.

### 케이스 훈련

- 특정 OLL/PLL/F2L 상태에 도달하도록 생성한다.
- 전체 상태에서 균등한 스크램블이 아니라는 점을 `케이스 훈련용`으로 표시한다.
- 사용자가 적용한 결과를 도식으로 확인할 수 있게 한다.

### 공식성 라벨

- `WCA 공식 스크램블`: 공식 대회에서 당시 공식 TNoodle로 생성·관리된 경우에만 사용
- `TNoodle 1.2.3으로 생성한 연습 스크램블 · 공식 대회용 아님`: 현재 프로토타입
- `연습용 random-state`: 후속 구현과 분포 검증을 마친 뒤 사용할 라벨
- `케이스 훈련용`: 의도적으로 상태를 제한한 스크램블

## 13. 카메라 인식 요구사항

### 현재 구현

- 임의 사진을 탐색하지 않고 화면의 고정 3면 안내선에 맞춘 두 포즈만 분석한다.
- 표준 6색 배치에서 `U/F/R` 포즈와 올바른 회전 관계의 `D/L/B` 반대 꼭짓점 포즈를 사용한다.
- 촬영 JPEG의 EXIF 방향을 적용하고 각 안내 사변형을 투시 보정한 뒤 3×3 내부 영역의 RGB 표본을 만든다.
- 여섯 센터를 기준으로 상대 조명 보정과 CIELab 거리 분류를 수행하여 54칸 후보와 셀별 신뢰도를 만든다.
- 사용자가 낮은 신뢰도 칸을 포함한 54칸을 확인·수정하면 `URFDLB` 상태를 재구성하고 색 수, 센터, cubie 유일성, 코너 방향 합, 엣지 뒤집힘 합, 코너/엣지 순열 parity를 검사한다.
- 합법 상태만 단계 진단과 `scanRecommendation` 대표 연습으로 연결하며, 촬영한 54칸을 연습 상태로 전달하거나 전체 해결 동작을 생성하지 않는다.
- 실제 iPhone이 연결되지 않아 카메라 권한·촬영과 조명·반사·재질별 정확도는 아직 실기기에서 검증하지 못했다.

### 목표와 한계

- 한 면씩 여섯 번 촬영시키지 않는다.
- 한 꼭짓점 주변의 세 면을 동시에 보는 포즈 A와 반대 꼭짓점의 세 면을 보는 포즈 B를 기본으로 한다.
- 각 포즈에서 거리, 흐림, 과노출, 반사, 가림을 실시간 안내한다.
- 센터를 기준으로 면 ID를 정하고, 두 포즈 사이 방향 관계를 추적하거나 사용자에게 확인받는다.
- 투시 보정 뒤 3×3 칸의 중앙/내부 영역에서 색 특징을 추출한다.
- 고정 RGB 임계값보다 촬영 내 상대 색 군집과 Lab/색도 특성을 우선한다.
- 스티커별 신뢰도를 보존하며 낮은 신뢰도만 수정하게 한다.
- 색 개수만 확인하지 않고 실제 3×3 큐브의 조각·방향·순열 불변식을 검증한다.
- 스캔 실패 시 수동 6면 입력, 다시 촬영, 불확실한 칸 수정 중 선택하게 한다.

세부 파이프라인은 [`ARCHITECTURE.md`](ARCHITECTURE.md)에 정의한다.

- 3×3 전용

- 단순하고 설명 가능한 간격 복습
- TNoodle-WCA 1.2.3으로 생성한 고유 3×3 연습 스크램블 32,768개

- 완전 로컬 기록

- 카메라 없이 모든 핵심 학습을 수행하는 대체 흐름

### MVP에서 제외

- 클라우드 계정, 소셜 피드, 리더보드

- 실기기 데이터셋 게이트를 통과하기 전의 `validatedScan` 학습 결과와 `검증됨` 라벨

## 16. 성공 지표

### 북극성 지표

**후속 주간 지연 물리 일치 케이스 수**: 지연 구간 저장을 추가한 뒤, `externallyPrepared`를 명시하고 도움·playback·인식 교정 없이 H0에서 실제 큐브를 수행해 기대 상태와 일치했다고 수동 보고한 고유 케이스 수를 본다. `validatedScan`을 도입하면 그 증거는 별도 표시한다.

단순 앱 실행일, 본 공식 수, 총 탭 수를 북극성 지표로 사용하지 않는다.

- 재촬영률
- 낮은 신뢰도 탐지의 정밀도/재현율
- 큐브 재질·조명·기기별 오류 편차

### 안전·신뢰 지표

- 카메라 권한 거부 후 핵심 과업 완료율
- 사진 원본 저장 0건이 기본값으로 유지되는지
- 잘못된 “유효 상태” 판정률
- 출처·라이선스 미확인 콘텐츠 0건
- 접근성 차단 이슈와 크래시 없는 세션 비율

### 가드레일

- 전체 stepper 공개율이 늘면서 후속 H0 지연 일치율이 떨어지면 성공으로 보지 않는다.
- 기록 단축이 특정 장치·고급 사용자에게만 나타나면 전체 효과로 과장하지 않는다.
- 연속 학습일을 위해 불필요한 알림이나 손실 회피 문구를 사용하지 않는다.

## 17. 분석 이벤트

개인정보를 최소화한 **후속 분석 이벤트 설계 예**(현재 `ReviewAttempt` 저장 스키마와 동일하지 않음):

- `review_started(caseID, priorState)`
- `hint_revealed(caseID, level)`
- `attempt_completed(caseID, startStateID, orientationID, maxHelp, comparison, evidence, delayBucket)`
- `scramble_generated(kind, generatorVersion)`
- `timer_completed(durationBucket, penalty, inspectionMode)`
- `scan_pose_completed(pose, qualityBucket)`
- `scan_corrected(stickerCountBucket)`
- `cube_state_validated(resultCategory)`

원본 사진, 정확한 촬영 위치, 사용자 얼굴, 자유 텍스트를 분석 이벤트에 넣지 않는다. 원격 분석은 별도 동의와 개인정보 고지 전에는 사용하지 않는다.

## 18. 수용 기준

MVP는 다음 조건을 모두 충족해야 한다.

- 기본 탭은 오늘·학습·연습·기록 네 개이며 사용자에게 트레이너 탭이나 `스피드 타이머`라는 별도 이름을 표시하지 않는다.
- `오늘`의 `연습 시작`은 화면을 push하지 않고 연습 탭으로 전환하며, 연습 탭에는 별도 허브나 타이머 상세 깊이가 없다.
- 연습 화면은 `ScrollView` 없이 인라인 내비게이션, 모드 선택, TNoodle 스크램블, 축약 전개도·U/F 기준, 타이머와 주요 조작을 한 화면에 표시한다.
- WCA 방식은 같은 주요 조작 영역에서 인스펙션을 시작하고 타이머 준비로 이어진다.
- 실행 중 화면 전체의 첫 touch-down은 정확히 한 번 정지하며, 정지당 기록 하나와 다음 스크램블 하나만 게시한다.
- 학습 화면은 모든 단서를 공개하고 열람·stepper 조작만으로 복습·완료·숙달 기록을 만들지 않는다.
- 이론 전용 레슨은 복습 큐와 회상 지표에서 제외된다.
- 복습 항목은 시작 상태·방향·move sequence·기대 상태·출처·권리 상태를 가진다.
- 모든 move와 stepper 중간·최종 상태가 Core 상태 적용 테스트를 통과한다.
- 사용자는 평문·공식 문자열을 답으로 입력하지 않고 실제 큐브를 수행한다.
- 사용자는 내부 H0–H5에 대응하는 도움을 순차적으로 열 수 있지만 UI에서 H 코드나 준비 방식 enum을 보지 않는다.
- `guidedAcquisition`, 준비 증거 누락, H1–H5, playback 또는 인식 교정을 사용한 시도는 독립 회상과 구분된다.
- MVP 시도 결과는 `matched/didNotMatch/unsure`와 `manualComparison`을 기록한다.
- 후속 `validatedScan`을 활성화하면 `검증됨`은 실기기 검증을 마친 파이프라인에서 유효 상태 검사와 기대 상태 비교를 통과한 결과에만 표시된다.
- 역공식 설정·예시 열람은 성공·완료·숙달로 집계되지 않는다.
- 불완전한 초급/2-Look 샘플에는 커리큘럼 완료율이나 숙달 문구가 나타나지 않는다.
- 동일한 스크램블 기록을 재현하고 파싱할 수 있다.
- 스크램블 표기와 54-facelet 전개도는 원자적으로 같은 상태를 가리키며, 어느 한쪽이라도 만들지 못하면 타이머를 시작할 수 없다.
- 검산 전개도는 흰색 U를 위, 초록 F를 앞에 둔다.
- 실행 중 화면 어디든 첫 touch-down으로 정지하고 중복 정지 요청은 하나의 기록만 만든다.
- 연습 화면은 방금 기록·페널티만 표시하고 PB·평균·추세는 기록 탭에만 표시한다.
- 검사 시간 15.00/17.00 경계가 규정 연습 모드에서 정확히 처리된다.
- 카메라 권한이 없어도 수동/도식 학습과 타이머를 사용할 수 있다.
- 스캔은 낮은 신뢰도 스티커와 불가능한 상태를 구분한다.
- 원본 사진은 기본적으로 저장하거나 업로드하지 않는다.
- 모든 내장 공식은 출처·버전·권리 상태를 가진다.
- VoiceOver, Dynamic Type, Reduce Motion의 핵심 흐름이 완료 가능하다.

### 출시 차단 조건

- **권리:** 내장 공식, 한국어 설명, 2D 도식, 애니메이션의 출처·배포 권리를 항목별로 증빙하지 못하면 해당 콘텐츠와 이를 전제로 한 커리큘럼 출시를 차단한다.
- **상표·메타데이터:** Rubik’s® 또는 WCA와의 제휴·공인을 암시하거나 불완전한 샘플을 `완전 입문`, `2-Look 숙달`, `검증된 학습법`으로 표현하면 App Store 제출을 차단한다.
- **실기기:** 물리 iPhone에서 카메라 권한, 촬영, 수정, 유효 상태, 삭제, VoiceOver·Dynamic Type·Reduce Motion 흐름을 통과하지 못하면 카메라 포함 출시를 차단한다.
- **검증 데이터:** 기기·조명·큐브 재질별 고정 데이터셋으로 스캔 오차를 평가하지 못하면 `검증됨` 라벨과 자동 상태 검증 마케팅을 차단한다.
- **배포:** 실제 앱과 일치하는 개인정보, 카메라 목적 문자열, 심사 메모, 스크린샷, TestFlight 최종 QA가 없으면 제출을 차단한다.

시뮬레이터 실행과 무서명 archive는 이 차단 조건을 해소하지 않는다. 상세 기준은 [`LEARNING_EXPERIENCE.md`](LEARNING_EXPERIENCE.md)와 [`APP_STORE_COMPLIANCE.md`](APP_STORE_COMPLIANCE.md)를 따른다.
