# CubeCoach 학습 경험 재설계

- 상태: Draft
- 기준일: 2026-07-31
- 적용 범위: 3×3×3, 한국어, 실제 큐브를 사용하는 학습 흐름
- 구현 상태: 2D net·move stepper·H0–H5·시각 인식 판별·수동 상태 비교까지 구현된 시뮬레이터 검증 프로토타입. 실기기 카메라와 콘텐츠 의미 검증은 남아 있음

## 1. 재설계 이유

기존 프로토타입은 일반적인 회상 연습과 분산 연습 연구를 근거로 **평문 질문, 머릿속 회상, 기억 난이도 자기평가**를 큐브 복습에 직접 적용했다. 이는 근거의 범위를 넘은 제품 추론이었다.

- 회상·간격 연구는 주로 단어, 텍스트, 사실, 수학·범주 과제를 다룬다.
- 큐브 공식은 **상태 인식, 기준 면 고정, 시공간 변환, 연속 손동작, 결과 상태 확인**이 결합된 시각·운동 기술이다.
- 일반 기억 연구는 평문 답안이나 “쉬움/어려움” 자기평가가 큐브 실행 능력을 타당하게 측정한다고 검증하지 않았다.
- 애니메이션, 관찰 학습, 운동 청킹 연구도 큐브 학습의 효과 크기나 최적 UI를 직접 검증하지 않았다.

따라서 새 계약은 설명을 써내는 능력이 아니라 **정해진 큐브 상태에서 올바른 방향으로 실제 동작을 수행하고 기대 상태와 비교하는 능력**을 연습한다. 자유 서술과 기억 난이도 평가는 복습에서 제거한다.

### 근거가 말하지 않는 것

- 평문 답안 또는 자기평가가 실제 큐브 실행을 정확히 예측한다는 것
- 2D, 3D, 영상 중 하나가 모든 큐브 학습자에게 항상 우월하다는 것
- 특정 H0–H5 순서가 큐브 학습에 최적이라는 것
- 앱의 복습 스케줄이 독립 솔빙이나 기록 단축을 보장한다는 것
- 일부 샘플 레슨을 완료하면 초급 해법 또는 2-Look CFOP를 숙달했다는 것

## 3. 학습 시도 계약

모든 복습 시도는 다음 순서를 따른다.

> **시작 상태 준비 증거 → 큐브 상태 → 방향 → 실제 동작 → 기대 상태 → 지연 회상**

1. **시작 상태 준비 증거:** 사용자가 앱 밖에서 화면과 같은 상태를 이미 만들었는지, 정답 역순의 설정 도움을 사용했는지 기록한다.
2. **큐브 상태:** 파서와 상태 적용 테스트를 통과한 2D net으로 시작 상태를 제시한다.
3. **방향:** `U/F/R` 기준 면과 사용자가 실제 큐브를 잡는 방향을 고정한다.
4. **실제 동작:** 사용자가 화면에 답을 쓰거나 디지털 큐브를 조작하지 않고 실제 큐브를 돌린다.
5. **기대 상태:** 단계별 또는 최종 2D net을 보여 주고 사용자가 실물과 비교한다.
6. **지연 회상:** 같은 세션의 즉시 반복과 구분되는 후속 시점에 동작열을 가린 상태로 다시 수행한다.

### 금지되는 답변 방식

- 공식 문자열 직접 입력
- 자연어로 동작 설명 입력
- 시각 후보에서 케이스를 고른 결과를 공식 실행의 정답으로 간주
- `쉬움/보통/어려움` 같은 기억 난이도 자기평가
- 화면 속 디지털 큐브 제스처를 실제 수행의 대리 지표로 사용

시각 후보 선택은 시작 상태를 구별하는 별도 `recognition` 증거로 사용할 수 있다. 그러나 케이스 이름을 맞힌 사실은 공식을 실제로 실행했다는 뜻이 아니며 실행 결과나 성공을 대신하지 않는다. 텍스트는 방향·접근성·오류 설명에 사용할 수 있지만 **공식 실행의 정답 입력 수단**으로 사용하지 않는다.

## 4. 학습과 복습의 경계

### 학습(Learn): 습득 지원

- 이론 전용 레슨: 큐브 구조, WCA 표기, 한국어 보조 용어, 해법 단계 개요
- 설정 가이드: 현재 구현은 정답 동작열의 역순을 사용해 완성 상태에서 연습 시작 상태를 만드는 2D stepper
- 전체 예시: 2D stepper로 현재 상태, 적용할 move, 다음 상태를 순서대로 표시
- 재생·이전·다음: 사용자가 속도를 통제하며 반복 가능
- 인식 단서·공식·회전별 전후 상태를 처음부터 숨기지 않고 모두 공개
- 화면 열람·stepper 조작만으로 `ReviewAttempt`, 복습 횟수, 숙달 상태를 생성하지 않음

역공식 설정은 답을 누설하지 않는 독립 테스트용 스크램블이 아니다. 학습 화면에서는 설정과 전체 stepper를 자유롭게 볼 수 있지만 열람 자체를 시도로 저장하지 않는다. 이후 복습 안에서 같은 설정 도움을 사용한 경우에만 내부적으로 `preparation=guidedAcquisition`, `playbackUsed=true`를 기록하고 독립 수행으로 집계하지 않는다.

### 복습(Review): 실행·지연 회상

- `트레이너`는 사용자-facing 영역이나 탭 이름이 아니다. 내부 `TrainerView`와 데이터 모델은 사용자에게 `복습`으로 제시한다.
- 이론만 있는 레슨은 복습 큐에 넣지 않는다.
- 유효한 시작 상태, 방향, 기대 상태, 검증된 move sequence가 모두 있는 항목만 복습에 들어간다.
- 사용자가 다른 연습이나 앱 밖에서 실물 큐브를 화면과 정확히 같은 상태로 이미 준비했다고 명시하면 `preparation=externallyPrepared`를 기록한다.
- 모든 시도는 실제 큐브 수행을 전제로 한다.
- 시도 직후에는 실물과 기대 상태를 비교하고, 이후 별도 시점에 다시 제시한다.

`H0`–`H5`, `externallyPrepared`, `guidedAcquisition`은 기록·스케줄링을 위한 내부 계약이다. UI는 이 코드를 노출하지 않고 `이미 같은 상태로 준비했어요`, `시작 상태 만드는 법 보기`, `방향 보기`, `첫 회전 보기`, `전체 회전 보기`처럼 사용자가 해야 할 행동을 말한다.

## 5. MVP 표현: 2D net + stepper

MVP는 장식적 3D 큐브보다 **결정적인 방향과 상태 변화**를 우선한다.

### 2D net

- 항상 같은 면 배치를 사용하고 `U/F/R/D/B/L` 라벨을 표시한다.
- 현재 기준 면과 움직이는 면을 색 외 테두리·패턴으로 구분한다.
- 케이스에 필요한 스티커만 강조하되 전체 방향 문맥은 유지한다.
- 시작 상태와 기대 상태에 안정적인 식별자를 연결한다.

### stepper

- 한 단계에 move 하나 또는 검수된 짧은 청크 하나만 표시한다.
- `이전 상태 → 적용 move → 다음 상태`를 함께 확인할 수 있다.
- 자동 재생은 보조 기능이며 이전·다음·일시정지가 항상 가능하다.
- Reduce Motion에서는 상태 간 정적 전환을 사용한다.
- 각 move의 상태 변화는 Core 상태 엔진으로 사전 검증한다.

### 후속 표현

다음 기능은 MVP 이후 검증한다.

- 조작 가능한 3D 큐브와 카메라 각도
- 화면 제스처로 move를 입력하는 디지털 연습
- 손잡이·핑거트릭 애니메이션
- 카메라 또는 스마트 큐브를 통한 실행열 자동 추적

3D와 디지털 제스처는 실제 큐브 수행을 보조할 수 있으나, 물리 실행 전이와 접근성을 사용자 테스트로 확인하기 전에는 기본 정답 채널로 사용하지 않는다.

## 6. 도움 사다리의 내부 계약

사용자 UI에는 H 번호를 표시하지 않는다. 아래 H0–H5는 열어 본 단서의 최고 수준을 저장하기 위한 내부 코드다.

| 단계 | 사용자에게 보이는 정보 | 시도 기록 |
| --- | --- | --- |
| H0 시작 상태 | 준비 방식을 기록한 뒤 케이스 이름과 공식을 숨긴 시작 2D 상태를 사용한다. 이어지는 시각 후보 선택은 인식 증거만 만든다. | `maxHint=H0` |
| H1 시각 인식 단서 | 케이스를 구별하는 스티커·조각 판별 단서 | `maxHint=H1` |
| H2 방향·표기 | 실제 큐브를 잡는 방향, `U/F` 기준 면, 시계 방향 판정과 표기 프라이머 | `maxHint=H2` |
| H3 첫 move | 첫 move와 적용 전·후 2D 상태 | `maxHint=H3` |
| H4 첫 의미 청크 | 첫 검수 청크의 move와 단계 이동 가능한 전·후 상태 | `maxHint=H4` |
| H5 전체 stepper | 전체 move sequence와 모든 단계의 기대 상태 | `maxHint=H5` |

규칙:

- 도움은 사용자가 명시적으로 한 단계씩 연다.
- 가장 높은 도움 단계는 수정하지 않는 시도 사실로 저장한다.
- `guidedAcquisition`, 준비 증거 누락, H1–H5 공개, stepper 조작·재생 또는 인식 교정을 사용한 시도는 지원된 수행이며 독립 시도로 집계하지 않는다.
- 독립 H0 후보는 사용자가 `externallyPrepared`를 명시하고 H1–H5·playback·인식 교정을 사용하지 않은 경우뿐이다.
- H0 결과도 현재 자동 검증이 없으므로 `검증됨`이 아니라 수동 비교 증거다.
- 오류 복구는 별도 습득 지원으로 제공하고 H6라는 숙련 단계로 만들지 않는다.

## 7. 시도 결과와 증거 수준

자기평가 대신 현재 구현이 저장하는 시도 사실을 기록한다.

### 현재 `ReviewAttempt` 저장 필드

| 필드 | 값 예 | 의미 |
| --- | --- | --- |
| `caseID` | 버전된 케이스 ID | 시도한 학습 케이스 |
| `startedAt` | 시작 시각 또는 `nil` | 시도 시작. 레거시 기록은 값이 없을 수 있음 |
| `timestamp` | 완료 시각 | 시도 순서와 복습 계산의 기준 |
| `preparation` | `externallyPrepared`, `guidedAcquisition`, 레거시 `nil` | 시작 상태를 준비한 방법 |
| `maxHint` | H0–H5 | 사용한 최고 도움 |
| `playbackUsed` | `true/false` | 역공식 설정 도움을 열었거나 회상 stepper를 조작·재생했는지 |
| `recognition` | `correct`, `corrected`, `notAssessed` | 시각 케이스 판별 증거 |
| `execution` | `matched`, `didNotMatch`, `unsure` | 사용자의 실물-기대 상태 비교 선택 |
| `evidence` | 현재 `manualComparison` | 결과의 근거 종류 |
| `mode` | `learning`, `review`, `practice`, `scanRecommendation` | 진입 경로 |
| `contentVersion` | `fnv1a64-…` | 케이스의 인식 설명·공식·설정·청크가 바뀌었는지 판별하는 결정적 버전 |

`preparation != externallyPrepared`, `maxHint > H0`, `playbackUsed=true`, 또는 `recognition=corrected`이면 지원된 시도로 분류한다. 레거시 `preparation=nil`도 독립 준비를 입증하지 못하므로 지원된 시도다. 현재 UI는 실행 뒤 `같아요/달라요/잘 모르겠어요`를 기록하며 자동 정확 판정을 하지 않는다. 기억 난이도 선택은 없고, 복습 스케줄 등급은 이 증거에서 내부 파생한다.

`contentVersion`은 프로세스마다 달라지는 Swift `Hasher` 대신 FNV-1a 64비트로 계산한다. 콘텐츠가 달라진 시도는 해당 케이스의 기존 스케줄을 그대로 이어 붙이지 않고 새 기준에서 계산한다. 이 값은 변경 감지용이며 보안 해시가 아니다.

### 후속 스키마 필드

`startStateID`, `orientationID`, `algorithmID`, `delayBucket`, `elapsed`는 제품 분석을 위한 후속 필드다. 현재 `ReviewAttempt`에 저장된다고 문서화하거나 현재 통계가 이 값을 제공한다고 주장하지 않는다.

### 용어 계약

- `일치 보고`: 사용자가 실물과 기대 상태가 같다고 선택한 `manualComparison`
- `불일치 보고`: 사용자가 다르다고 선택한 `manualComparison`
- `모름 보고`: 사용자가 정확히 비교하지 못했다고 선택한 결과
- `독립 시도`: `externallyPrepared`를 명시하고 H0에서 인식 교정과 playback 없이 수행한 시도. 자동으로 성공이나 숙달을 뜻하지 않음
- `지원된 시도`: `guidedAcquisition`·준비 증거 누락·H1–H5·인식 교정·playback 중 하나 이상이 있는 시도
- `숙달`: 완전한 커리큘럼, 사전 정의한 지연·전이 기준, 검증 계획이 모두 갖춰지기 전에는 제품 문구로 사용하지 않음

`validatedScan` enum은 향후 호환성을 위해 존재하지만 **복습 사후 정확 비교에는 아직 통합되지 않았다**. 현재 카메라는 두 포즈에서 복원·유효 상태 검사 후 학습 단계를 진단하고 `mode=scanRecommendation`인 대표 연습을 추천할 뿐이다. 추천 화면의 시작 전개도는 촬영한 54칸 상태 자체가 아니다. 물리 시도 뒤 기대 상태와도 자동 비교하지 않는다. 실제 iPhone 데이터셋 검증과 사후 비교 통합을 마친 결과에만 `evidence=validatedScan`과 `검증됨` 라벨을 사용할 수 있다. 이 결과도 최종 상태 일치의 증거이지 개별 move의 순서나 손동작을 추적한 증거는 아니다.

1. `학습 → 설명·인식 단서·공식 전체 공개 → 설정·실행 stepper 관찰 → 실제 큐브로 따라 하기 → 기록 없이 종료`
2. `오늘/학습 상세 → 복습 → 외부 준비 확인 또는 시작 상태 만들기 도움 → 단서를 가린 시도 → 필요 시 도움 → 기대 상태 비교 → 결과 저장`
3. `지연 큐 → 외부 준비 확인 → 동작열을 가리고 수행 → 기대 상태 비교`
4. 현재: `선택적 스캔 → 유효 상태 확인 → 단계 진단 → 대표 연습 추천`. 후속: 촬영 54칸을 연습 상태로 전달하고 물리 시도 뒤 기대 상태와 비교해 검증 결과 저장
5. `오늘의 연습 시작 → 연습 탭 전환 → 한 화면에서 모드·스크램블·U/F 검산 → 같은 주요 조작 영역에서 인스펙션 또는 측정 → 화면 전체 touch-down 정지 → 최신 기록·페널티와 다음 스크램블`

## 9. 수용 기준

- 기본 탭은 오늘·학습·연습·기록 네 개이며 트레이너를 독립 탭으로 노출하지 않는다.
- 오늘의 연습 CTA는 새 화면을 push하지 않고 연습 탭으로 전환한다.
- 연습 탭은 중간 허브와 `ScrollView` 없이 인라인 내비게이션·모드·TNoodle 스크램블·축약 전개도와 U/F 기준·타이머·주요 조작을 한 화면에 맞춘다.
- 일반 측정과 WCA 방식 인스펙션은 같은 주요 조작 위치를 사용한다.
- 실행 중 화면 전체의 첫 touch-down은 한 번만 정지하며, 정지 상태는 최신 시간·페널티만 표시하고 다음 스크램블을 정확히 한 번 게시한다.
- PB·평균·추세 등 솔브 통계는 기록 탭만 소유하고 연습 탭은 중복 표시하지 않는다.
- 학습 열람·stepper 조작만으로 `ReviewAttempt`를 생성하지 않는다.
- 이론 전용 레슨은 복습 큐와 회상 지표에서 제외된다.
- 복습에는 유효한 시작 상태·방향·move sequence·기대 상태가 모두 있는 항목만 들어간다.
- 모든 move와 각 stepper 상태가 Core 상태 적용 테스트를 통과한다.
- 사용자는 평문 또는 공식 문자열을 답으로 입력하지 않는다.
- 사용자는 실제 큐브 수행 뒤 `matched/didNotMatch/unsure` 중 하나를 수동 비교로 기록한다.
- 현재 결과는 `manualComparison`이며 UI에 `검증됨`을 표시하지 않는다.
- `validatedScan`은 실기기 데이터셋과 사후 기대 상태 비교가 통합되기 전에는 결과로 생성하지 않는다.
- 시작·완료 시각, 준비 방식, H0–H5 최고 도움, playback, 시각 인식 정답·교정, 실행 비교, 증거, 모드, 결정적 콘텐츠 버전이 시도 기록에 남는다. 지연 구간은 후속 필드다.
- `externallyPrepared`가 아니거나 H1–H5, playback, 인식 교정을 쓴 결과는 독립 회상으로 집계되지 않는다.
- 사용자 UI에는 `Trainer`, H0–H5 코드, `externallyPrepared`, `guidedAcquisition`을 노출하지 않는다.
- 역공식 설정과 전체 예시 열람은 습득 지원으로 간주하며, 학습 화면에서 본 것만으로 시도·성공·숙달 기록을 만들지 않는다.
- `scanRecommendation`은 스캔 단계에 따른 대표 복습 추천이며 촬영한 54칸 상태 자체를 복습에 전달했다고 표시하지 않는다.
- 불완전한 초급/2-Look 샘플 커리큘럼은 완료율이나 숙달률을 표시하지 않는다.
- VoiceOver, Dynamic Type, Reduce Motion으로 2D net·stepper·비교 선택을 완료할 수 있다.

## 10. 구현 단계

### Phase 0 — 콘텐츠·권리 게이트

- 각 항목에 시작 상태, 방향, move sequence, 기대 상태, 출처, 버전, 권리 상태를 부여한다.
- WCA Article 12 파서와 상태 적용 테스트로 표기·결과를 검증한다.
- 외부 공식 가이드의 문구·도식·영상은 링크와 참고 근거로만 사용하고 복제 허가를 별도 확인한다.
- 권리 또는 정확성이 미확인인 항목은 앱 번들에서 제외한다.

### Phase 1 — 2D 습득 경험: 프로토타입 구현

- 고정 방향 2D net, move 단위 stepper, 정답 역순의 설정 가이드를 구현했다.
- 이론 레슨과 실행 가능한 항목을 데이터 모델에서 분리했다.
- VoiceOver 대체 텍스트와 Reduce Motion 분기를 구현했으며 실기기 접근성 QA는 남아 있다.

### Phase 2 — 물리 복습 MVP: 프로토타입 구현

- 명시적 `externallyPrepared/guidedAcquisition` 준비 증거, H0–H5, 시각 인식 증거, 실물-기대 상태 수동 비교와 현재 `ReviewAttempt` 필드를 구현했다.
- 자유 서술·공식 입력·기억 난이도 자기평가를 제거했다.
- `scanRecommendation`을 대표 연습 추천으로 표시하고 수동 비교 결과에 `검증됨`을 표시하지 않는다. 촬영 54칸 상태 전달, `validatedScan`, 지연 구간 저장은 후속이다.

### Phase 3 — 스캔 검증

- 실제 iPhone 데이터셋으로 두 포즈 촬영, 수정, 상태 유효성, 기대 상태 비교를 검증한다.
- 지원 기기·조명·큐브 재질별 오차와 실패 조건을 공개한다.
- 통과한 결과에만 `스캔 검증` 증거를 부여한다.

### Phase 4 — 확장 표현·자동 실행 검증

- 3D, 디지털 제스처, 카메라 move tracking, 스마트 큐브 연동을 각각 실험한다.
- 실제 큐브 전이, 오류율, 접근성, 기기 성능이 2D MVP보다 나은지 확인한 뒤 기본 경험 채택을 결정한다.

## 12. 한국어 표기 관례

- 기준 표기는 영문 WCA Article 12의 `F/B/R/L/U/D`, `'`, `2`, `x/y/z`다.
- 공식 카드와 단계 버튼은 표준 기호를 변형하지 않는다. 반시계를 `*`, `-`, `i`로 바꾸지 않는다.
- `시계 방향`, `반시계 방향`, `180도` 설명은 별도 `기호 읽는 법` 섹션에서만 제공한다. 공식 실행 화면은 `R U R' U'`처럼 기호 자체에 집중한다.
- 한국어 최초 노출은 `윗면(U)`, `앞면(F)`, `오른쪽 면(R)`처럼 병기한다.
- 음성 읽기는 `알`, `알 프라임`, `알 투`를 기본 후보로 두되 사용자 테스트 전에는 표준 발음이라고 주장하지 않는다.
- [WCA 규정 번역 목록](https://www.worldcubeassociation.org/regulations/translations/)은 한국어 2026-04-01판을 제공한다. 번역은 편의를 위한 비공식 문서이며 정확하지 않을 수 있으므로 현재 영문 규정과 충돌하면 [영문 원문](https://www.worldcubeassociation.org/regulations/full/#article-12-notation)을 따른다. 한국어의 `앞면/뒷면/오른쪽 면/왼쪽 면/윗면/아랫면`, `시계 방향/반시계 방향` 용례만 UI 참고로 사용한다.
- 국내 강사·사용자 검수 전에는 `역알`, `섹시무브` 같은 커뮤니티 표현을 기본 용어로 고정하지 않는다.

한국어 용어의 친숙성은 국내 사용자 테스트로 검증한다. 규정 표기 정확성과 현지 발음·별칭의 익숙함은 별개의 요구사항이다.
