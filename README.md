# CubeCoach

CubeCoach는 3×3×3 큐브를 **대신 풀어 주는 앱이 아니라**, 사용자가 공식을 기억하고 케이스를 인식하며 실제 솔빙 실력을 높이도록 돕는 iOS 코치입니다.

카메라 인식은 사용자의 큐브 상태에서 다음 연습 목표를 찾는 입력 수단이며, 정답 동작을 끝까지 지시하지 않습니다. 현재 구현은 표준 6색 배치의 큐브를 `U, F, R, D, B, L` 순서로 한 면씩 안내선에 맞춰 촬영하고, 기기 안에서 54칸 후보를 복원합니다. 사용자가 전개도를 확인·수정해 합법 상태 검사를 통과하면 검토한 `URFDLB` 54칸과 흰색 U 위·초록색 F 앞 방향을 전용 메모리 내 상태 연습 세션으로 함께 전달합니다. 이 흐름은 별도 스크램블이나 해결 동작을 만들지 않으며 임의 사진 속 큐브를 찾아내는 범용 detector도 아닙니다.

## 제품 원칙

- **학습과 복습의 역할을 나눈다.** 학습에서는 설명·인식 단서·공식·회전별 전후 상태를 모두 보고 따라 돌린다. 복습에서는 단서를 가리고 실제 큐브로 수행한 뒤 기대 상태와 비교한다.
- **열람을 성취로 세지 않는다.** 학습 화면을 본 것만으로 복습 기록이나 숙달 상태를 만들지 않는다.
- **도움은 행동으로 이름 붙인다.** 사용자는 `방향 보기`, `첫 회전 보기`, `전체 회전 보기`처럼 필요한 단서를 연다. `H0`–`H5`, `externallyPrepared`, `guidedAcquisition` 같은 이름은 내부 기록 계약에만 사용한다.
- **실제 큐브로 수행한다.** MVP는 2D net과 단계 이동 가능한 stepper를 사용하며 화면 관찰이나 디지털 제스처를 물리 실행으로 간주하지 않는다.
- **증거를 구분한다.** 일반 복습은 실물-도식 수동 비교를 기록한다. 상태 연습은 검토한 시작·결과 스캔의 목표 조건을 비교하지만, 실기기 정확도 매트릭스가 끝나기 전에는 이를 `검증됨` 마케팅·학습 증거로 표시하지 않는다.
- **정직하게 이름 붙인다.** 앱의 연습용 스크램블을 “WCA 공식 스크램블”이라고 부르지 않는다.
- **자동 해결은 보조 분석이다.** 최단·준최단 해법은 비교 학습이나 사후 분석에 쓰며 기본 경험이 아니다.

자세한 학습 계약은 [`docs/LEARNING_EXPERIENCE.md`](docs/LEARNING_EXPERIENCE.md), 제품 범위는 [`docs/PRODUCT_SPEC.md`](docs/PRODUCT_SPEC.md), 설계 계약은 [`DESIGN.md`](DESIGN.md), 기술 경계는 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)를 참고하세요.

## 목표 경험

1. `학습`에서 설명·인식 단서·공식·회전별 전후 상태를 모두 보고 실제 큐브로 따라 한다. 이 열람은 기록을 만들지 않는다.
2. 학습 상세 또는 `오늘`에서 `복습`을 열고, 단서를 가린 시작 상태에서 실제 큐브로 공식을 떠올린다.
3. 필요한 경우에만 방향·첫 회전·회전 묶음·전체 회전을 차례로 연다.
4. 실제 큐브와 기대 2D 상태를 비교한 결과까지 제출하면 복습 기록을 저장한다. 평문·공식 문자열 답안과 기억 난이도 자기평가는 받지 않는다.
5. `연습` 탭을 열면 추가 화면을 거치지 않고 한 화면의 TNoodle 연습 스크램블, 축약 전개도와 U/F 기준, 타이머를 바로 사용한다. `오늘`의 `연습 시작`도 화면을 쌓지 않고 이 탭으로 전환한다.
6. 연습 화면은 스크롤하지 않는다. 일반 측정과 WCA 방식 연습 모두 같은 주요 조작 영역에서 준비·인스펙션·시작을 이어 가며, 실행 중에는 화면 어디든 첫 touch-down으로 정지한다.
7. 정지 뒤에는 방금 기록과 페널티만 보여 주고 다음 스크램블을 정확히 한 번 게시한다. PB·평균·추세 등 통계는 `기록` 탭에서만 확인한다.
8. 스캔한 상태가 이미 완성돼 있으면 일반 타이머로 돌아간다. 미완성 합법 상태라면 촬영 상태와 U/F 방향을 그대로 유지하고, 먼저 목표를 본 뒤 스크램블·해결 동작 없이 상태 연습을 시작한다.
9. 상태 연습은 단조 활성 시간만 재고 화면 전체의 첫 touch-down으로 멈춘다. 멈춘 동안 개념 힌트를 단계별로 열거나 같은 방향으로 결과를 다시 촬영해 목표 달성·개선·변화 없음·후퇴를 비교할 수 있다. 이 시도는 일반 타이머·학습 통계에 저장하지 않는다.

## 현재 저장소 범위

이 저장소는 시뮬레이터와 자동 테스트로 검증 중인 프로토타입입니다. 2026-07-31 현재 다음 기반을 포함합니다.

- Swift 6 기반 `CubeCoachCore` 패키지
- iOS 17 이상을 대상으로 하는 SwiftUI 앱 구조
- 네 개 기본 탭: 오늘, 학습, 연습, 기록
- 226개 실행형 학습 항목을 담은 학습 로드맵(초급 10, 완결 2-Look 15, Full CFOP 119, COLL 40, Roux CMLL 42), 계열별 검색, 모든 단서를 공개하는 학습 상세, 고정 방향 2D net과 move stepper, 단서를 가린 사용자-facing 복습, 로컬 학습 진행도 UI
- Singmaster 표기 파싱, 서명된 TNoodle-WCA 1.2.3으로 사전 생성한 **32,768개 3×3 연습 스크램블** 카탈로그, 타이머·통계 도메인
- 스크램블 표기와 이를 완성 큐브에 적용한 54칸 검산 전개도의 원자적 갱신. 흰색 U가 위, 초록 F가 앞인 기준이며 둘 중 하나라도 검증하지 못하면 타이머를 잠금
- 별도 깊이와 `ScrollView` 없이 인라인 내비게이션·모드 선택·스크램블·축약 전개도·타이머를 한 화면에 배치한 연습 루트
- 타이머 실행 중 전체 화면의 첫 touch-down 정지, 실행 중 화면 chrome 숨김, 중복 정지 요청 무시
- 정지당 정확히 한 번 게시되는 다음 스크램블, 타이머의 방금 기록·페널티 수정과 기록 탭의 PB·평균·추세·최근 기록 통계 분리
- `U, F, R, D, B, L` 여섯 면의 정면 촬영, 표준 상단 방향 안내, 외곽면 또는 네 모서리 스티커로 복원한 투시 사각형 기반 보정, 완화된 정렬·노출·선명도 자동 셔터, 셀 색 분산과 자동 촬영의 셔터 전후 9칸 일치 검사를 통과한 면만 수락하는 품질 gate
- 중앙 로고를 피한 센터 표본, 촬영 단계의 센터색 분리 검사, 여섯 센터를 기준으로 색마다 정확히 9칸을 배정하는 전역 색 분류, 강제 보정·낮은 신뢰도 공개, 자동 54칸 후보 복원
- 54칸 전개도 검토, 선택 대상·현재 색·적용 결과가 보이는 3×2 색상 inspector, 선택한 면 재촬영, 사진 없이 직접 입력하는 대체 흐름
- 색 수량·엣지/코너 조합·방향 합·cubie permutation parity를 위치와 가능한 색 조합으로 안내하는 상태 진단
- 검토한 합법 `URFDLB` 54칸과 identity U/F 방향을 전용 메모리 내 상태 연습으로 원자 전달. 목표 우선 안내, 스크램블·생성 해법 없는 실행, 단조 활성 타이머, 전체 화면 touch-down 정지, 일시정지 중 단계별 개념 힌트, 같은 방향 결과 재촬영과 Core 목표 조건 비교, 막힘·실패 시 관련 학습 연결
- 최고 기록, 전체 평균, 완주율, 기록 편차, current/best Ao5·Ao12와 최근 기록 추세를 제공하는 기록 화면
- 앱 내 개인정보 처리방침 링크와 모든 로컬 학습·솔브 데이터 삭제

다음 항목은 아직 제품 수준으로 완성되었다고 보지 않습니다.

- 무제한 네이티브 random-state 생성기와 공식 대회용 스크램블 운영
- 임의 배경·방향의 사진에서 큐브를 찾는 범용 detector
- 비표준 색 배치와 모든 조명·반사·가림·스티커리스 재질에서 무수정 인식을 보장하는 색상 모델
- 정확한 OLL/PLL 개별 케이스 matcher 또는 촬영 상태의 전체 해결열 생성
- 상태 연습 시도를 일반 타이머·복습 스케줄·학습 통계에 통합하는 기능
- App Store Connect 메타데이터·배포 서명, 접근성·현지화와 실기기 카메라 최종 QA

따라서 현재 카메라 기능은 **가이드 안에 둔 표준 6색 큐브**만 지원합니다. 자동 셔터는 사진을 찍을 시점만 판단하며 색상 인식 성공을 뜻하지 않습니다. 최종 촬영본의 검출 영역·셀 색 분산·셔터 전후 색 일치를 별도로 검사하고, 의심되는 면은 완료 처리하지 않은 채 같은 면에서 재촬영합니다. 54칸 복원 뒤에도 낮은 신뢰도와 cubie 오류를 숨기지 않고 실물 큐브 대조를 요구합니다. iPhone 13 mini와 iPhone 17 Pro 물리 기기에서 조명·반사·재질별 임계값과 실제 인식 정확도는 아직 교정·확정하지 않았습니다. 현재 스크램블은 공식 서명 JAR의 출력을 고정 번들로 제공하지만, 유한 카탈로그에서 선택한 개인 연습용이며 공식 대회 스크램블 세트가 아닙니다.

## 개발 환경

- macOS와 Xcode
- Swift 6
- iOS 17 이상 실기기 또는 시뮬레이터
- 카메라 흐름 검증에는 실기기가 필요

## 빌드와 테스트

코어 패키지:

```bash
swift test
```

iOS 앱:

```bash
open CubeCoach.xcodeproj
```

Xcode에서 `CubeCoach` 스킴과 iOS 17 이상 대상을 선택해 실행합니다. 시뮬레이터에서는 학습·타이머·기록·수동 스캔 흐름을 확인할 수 있고, 실제 촬영·권한 흐름은 카메라가 있는 iPhone에서 검증해야 합니다.

로컬 Xcode 26.6의 `IDESimulatorFoundation`/`DVTDownloads` 불일치는 `xcodebuild -runFirstLaunch`와 iOS 플랫폼 재설치로 정합화했습니다. 최신 전체 `swift test`는 Swift Testing 226개와 XCTest 4개가 통과했고, strict concurrency·`GCC_TREAT_WARNINGS_AS_ERRORS=YES` iPhone 13 mini·iPhone 17 Pro Simulator 빌드, 정적 분석과 Apple Development 서명 generic iOS 빌드도 성공했습니다. 최신 개발 빌드는 연결된 iPhone 13 mini에 설치·실행했습니다. iPhone 13 mini와 iPhone 17 Pro Simulator에서는 상태 연습의 브리핑·일시정지·결과 레이아웃이 잘리지 않음을 확인했습니다. 사용자는 물리 iPhone 13 mini에서 촬영이 확실히 빨라졌고 큐브 상태도 정상 인식된다고 정성 확인했습니다. 물리 기기의 상태 연습 전체 상호작용과 조명·반사·재질·손떨림을 아우르는 카메라 정확도 매트릭스는 아직 완료하지 않았습니다.

## 조사 범위와 한계

문서는 2026-07-31에 확인한 대표적·권위 있는 공개 자료를 우선합니다. WCA 규정과 Apple 공식 문서, 동료평가 연구는 제품 요구의 근거로 사용하고, 커뮤니티·튜토리얼 자료는 용어와 관행을 파악하는 참고 자료로만 구분합니다.

기존 평문·자기평가형 트레이너는 일반 회상·분산 연습 근거를 큐브의 시각·운동 기술에 과도하게 확장한 프로토타입이었습니다. 새 계약은 이를 큐브 전용으로 검증된 방법이라고 주장하지 않으며, 2D 상태·방향·실제 동작·기대 상태 비교와 지연 재시도를 제품 가설로 검증합니다.

대한민국과 해외의 “모든” 문서·게시물·영상을 완전히 망라했다고 주장하지 않습니다. 로그인 전용 커뮤니티, 검색 차단 페이지, 영상 내부 내용, 삭제·수정 가능한 게시글은 제한적으로만 확인했습니다. 자세한 출처와 품질 구분은 [`docs/RESEARCH.md`](docs/RESEARCH.md)에 기록합니다.

## 법적·브랜드 주의

- World Cube Association 규정과 명칭을 준수하되, CubeCoach는 WCA가 승인하거나 운영하는 앱이 아닙니다.
- 공식·도식·영상은 저작권이 있을 수 있습니다. 제품에 포함하기 전 원출처, 사용 허가, 라이선스, 표기 의무를 별도로 검수해야 합니다.
- Rubik’s Cube 및 관련 표장은 각 권리자의 상표일 수 있습니다. 제품명과 마케팅 문구에서 제휴·공인을 암시하지 않습니다.
